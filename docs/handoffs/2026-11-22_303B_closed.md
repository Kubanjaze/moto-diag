## What shipped

In `moto-diag-mobile`, pull request #11 (head `b7ad88f`), built by the
operator's own session and merged by the operator as `2f6739c`:
- **Signing in.** Staff sign in with a username and password, through the
  server's `POST /v1/auth/login` (Phase 303). The token is kept in the same
  Keychain slot as a pasted key and sent the same way, so nothing else in
  the app changed to carry it.
- **Who is signed in.** The home screen says "Signed in as" the person's
  name, from `GET /v1/auth/me`, and never shows the token. With nothing
  stored it offers "Sign in" and "Use an API key instead"; a pasted key
  keeps its old view.
- **Signing out.** The push token is dropped first, then the sign-in is
  ended on the server (`POST /v1/auth/logout`), then the slot is cleared. A
  failed network call never leaves anyone stuck signed in.
- **An ended sign-in.** When the server no longer knows a sign-in token
  (expired after 30 days, or ended elsewhere), the app clears the slot once
  and opens the sign-in box saying "Your sign-in has ended. Please sign in
  again."
- **No server change.** The pasted key stays as a second way in.
