## What 353 learned that the next content phase should not relearn

- **An image-only page defeats a text search, and the negative looks
  exactly like a real one.** 354 concluded that the CHF50 manual "prints the
  model only as CHF50" after finding "metropolitan" 0 times in 319 pages of
  text. The cover has no text layer, and rendered it reads "CHF50/P/S
  METROPOLITAN™" and "2002–2006" (F152). Render the title page before any
  claim about a document's identity.
- **A file name is still not an identity.** "Fiddle III" came from a file
  name: the manual prints only "MODEL XA05W-6". This was 354's lesson
  (F150), made again one phase later.
- **A column is not a manual.** Two draft errors here were one machine's
  column applied to another: the Fly 125's automatic starter given to the
  Fly 50 (20 Ω / 5 min against 6 Ω / 15 min), and the B 125 engine's Walbro
  given to the Beverly 125.
- **Extract every PDF, then select by vocabulary.** 354's file-name filter
  missed the four Ruckus owner's manuals, which were in the library the
  whole time.
- **`git merge -F -` does nothing.** Git does not read the message from
  stdin, and master stays where it was. Use a message file.
- **The pipeline is on disk**: `~/research/motodiag/353_step0/` has
  `extract.py` (every PDF, no name filter), `select_pages.py`, `sweep.py`,
  `verify.py`, `show.py` (print a page) and `check_quotes.py` (every quote
  in a seed file against its make's documents, with a planted fake as the
  positive control). The extracted page text is in `pages/`.
