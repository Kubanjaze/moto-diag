### Step 2: check 404 and 405 from the Mac, on the merged code

**Which computer:** the Mac. **Which window:** Terminal. Only after step 1
printed ALL GOOD.

The Mac's own copy of the code goes onto master first. This matters: when
the Mac checks live, it tells the home desktop which commit to check with,
and the desktop runs that commit's deploy check. With the Mac on an older
commit, 404's live check would run the old deploy check and fail on the
payments feed's writes. So the block stops unless the Mac's copy is at the
merge, with nothing changed by hand.

Then it checks two phases, read-only:
- **404:** its live check should pass, with the payments feed's writes
  shown in the listed lines.
- **405:** its live check should print "has no dry-run diff: no deploy to
  verify" and pass; it lists nothing, because 405 changed nothing on live.

If the desktop's own development copy of the code has changes in it, the
live check refuses and this block prints SOMETHING IS OFF: that copy is
then tidied at the desktop itself, not from the Mac.

405's own checks end at its last commit before the advisor's merge of
master, `e4a2147`, not at the merge: the merge also carries 407's code,
which those checks would count as code changed after 405's test run, and
the first check looks a commit up by its short name. (Corrected by the
advisor before the merge; the block first named the merge.)

```bash
bash <<'EOF5'
set -u

R=Kubanjaze/moto-diag
```
