What it does, in order:

**Corrected on 2026-11-20, before it ran.** The block first written here
asked `sudo -n -l <command>` whether each approved restart ran without a
password, and whether `restart ssh.socket` did. That question gets yes for
any command lilcu may run with a password, which is every command (Phase
390 measured it on the desktop). So the block would have installed
correctly, then stopped on a false SOMETHING IS OFF. The block below reads
the rule files instead. The phase log, 2026-11-20, has the bench.

```bash

  command -v "$T" >/dev/null 2>&1 || bad "this computer has no $T command; nothing was changed, so bring this to the advisor"

echo "Your Ubuntu password, once, to install the Mac's new steps:"

GOT=$(sha256sum < "$DISPATCHER" | cut -c1-64)
WANT=$(sha256sum < "$DEV/ops/desktop/motodiag_remote.py" | cut -c1-64)
[ "$GOT" = "$WANT" ] || bad "the installed list of steps is not the merged one; bring this to the advisor"
echo "Checking what now runs without a password..."
SAID=$(sudo -n cat "$API" </dev/null) || bad "the new password-free restarts could not be read back; bring this to the advisor"

SRC="/etc/sudoers /etc/sudoers.d"
[ -e /etc/sudoers-rs ] && SRC="$SRC /etc/sudoers-rs"
FREE=$(sudo -n grep -RlE '^[[:space:]]*[^#[:space:]].*(NOPASSWD|!authenticate)' $SRC </dev/null) || bad "the list of what runs without a password could not be read; bring this to the advisor"
OTHER=""
while IFS= read -r F; do
  case "$F" in
    "$API") ;;
    "$TRIM") [ "$(sudo -n cat "$TRIM" </dev/null)" = "$TRIM_RULE" ] || OTHER="$OTHER $F" ;;
    *) OTHER="$OTHER $F" ;;
  esac
done <<< "$FREE"
[ -z "$OTHER" ] || bad "the Mac's new steps are installed, but more than you approved runs without a password here (in:$OTHER); bring this to the advisor"
sudo -k </dev/null
echo "The Mac's way in has the new steps. Without a password, this computer runs only what you approved: the restarts, and the disk clean-up from before."
```
