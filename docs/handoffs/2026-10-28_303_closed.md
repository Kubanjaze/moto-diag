## What shipped

- **Staff logins.** `motodiag user create / list / set-password /
  deactivate / sessions` (`cli/user.py`). A password is hashed with scrypt
  from the standard library (`auth/passwords.py`), at least 8 characters,
  never printed, logged or put in `--json`. Roles stay as they are:
  `shop member add --role owner|tech|service_writer|apprentice`.
- **Sessions are rows of `api_keys`** (the operator's part (a)): `mds_`
  for a session, `mdk_` for a key, no migration (`auth/sessions_repo.py`).
  A session lives 30 days from `created_at` (`session_lifetime_days`),
  compared as UTC times. `apikey list` and `apikey show` leave sessions
  out.
- **`/v1/auth/*`**: login, me, logout, sessions (list, end one), change
  own password, and the owner's reset of a member's password, which needs
  `manage_users` at that shop and refuses an owner at any shop and a
  member of any other shop (K56). Every login failure is one 401
  `login-failed`, timed the same (a dummy hash on both failing paths).
- **One credential, one tier** (`auth/deps.py`): every route and the live
  socket take a session or a key; a session's tier is the user's own
  subscription, else the highest of an owner of a shop they belong to
  (part (c)). The socket takes a session only through the bearer
  subprotocol; `serve` filters `mds_` tokens out of uvicorn's logs.
  `request.state.caller` is left for Phase 348.
- **Guides:** `docs/guide/api.md` (a staff login, an API key) and
  `docs/guide/shop-workflow.md` (create the user before adding them).
- **Findings F231** (an Engineer's rule-1 stop has no way back into the
  fleet) and **F232** (a migration has no path through the fleet), filed
  as F229 and F230 and renumbered after master took those numbers.

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Paste this whole block once 303 is merged to `master`. It asks

```bash
bash <<'EOF2'
set -u

bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
```

### Step 2: the first staff login, and a test login

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal, after step 1 printed ALL GOOD. It asks for the person's login
name, their full name, the shop's number and their role, then for their
password twice (nothing shows as you type). It creates them, gives them
their role, logs in once as them, and logs out again. Have the shop's
number ready: the block prints the list of shops first.

```bash
bash <<'EOF2'
set -u
SRV=~/motodiag/server
export MOTODIAG_DB_PATH=~/motodiag/live/motodiag.db
MD="$SRV/.venv/bin/motodiag"
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
"$MD" shop profile list </dev/null || bad "could not list the shops"
read -r -p "Their login name: " U </dev/tty
read -r -p "Their full name: " N </dev/tty
read -r -p "The shop's number (from the list above): " S </dev/tty
read -r -p "Their role (owner, tech, service_writer or apprentice): " R </dev/tty
read -r -s -p "Their password (at least 8 characters): " P1 </dev/tty; echo
read -r -s -p "The same password again: " P2 </dev/tty; echo
[ "$P1" = "$P2" ] || bad "the two passwords were not the same; nothing was created"
printf '%s\n' "$P1" | "$MD" user create --username "$U" --full-name "$N" --password-stdin || bad "the user was not created"
ID=$("$MD" user list --json </dev/null | python3 -c "import json,sys; print(next(u['id'] for u in json.load(sys.stdin) if u['username']==sys.argv[1]))" "$U") || bad "could not find the new user"
"$MD" shop member add --shop "$S" --user "$ID" --role "$R" </dev/null || bad "the role was not given"
OUT=$(U="$U" P="$P1" python3 -c "
import json, os, urllib.request
req = urllib.request.Request('http://127.0.0.1:8000/v1/auth/login',
    data=json.dumps({'username': os.environ['U'], 'password': os.environ['P'], 'client': 'first-login check'}).encode(),
    headers={'Content-Type': 'application/json'})
body = json.load(urllib.request.urlopen(req))
for m in body['memberships']:
    print('Logged in; shop', m['shop_id'], 'as', m['role'])
out = urllib.request.Request('http://127.0.0.1:8000/v1/auth/logout', method='POST',
    headers={'Authorization': 'Bearer ' + body['token']})
print('Logged out:', urllib.request.urlopen(out).status)
") || bad "the test login did not work"
echo "$OUT"
echo "$OUT" | grep -q "Logged out: 204" || bad "the test login did not log out"
echo "ALL GOOD"
EOF2
```
