## What shipped

A new shop is set up from the server's command line in one sitting:
- **`motodiag shop onboard run`** walks the owner through five steps, in
  order: the shop's profile; the owner's own login, made the shop's owner;
  the staff, each with a login and a role; the Terms of Service, accepted
  by the one owner who says they are at the keyboard, for themselves; and
  the bikes, from a CSV file or typed one at a time, each linked to a
  customer under the shop. Each step can be skipped, and a step already
  done prints what is there and asks nothing, so it is safe to run again.
  It ends by offering one checklist walked through on the terminal (the
  existing `workflow run`, which saves nothing), then a closing screen of
  what to do next. With several shops it needs `--shop`, and refuses
  otherwise, writing nothing.
- **`motodiag shop onboard import-bikes FILE`** is the import on its own,
  with `--dry-run`. Every row is checked before any is written. A bike is
  matched only by its VIN; a customer only within the shop, by exact
  phone, else exact name.
- **`motodiag shop onboard status`** says which of the five are done, for
  one shop or every shop, and never refuses.
- **The guide,** `docs/guide/shop-workflow.md` section 0, has a paragraph
  on the three commands.

Nothing existing changed: the wizard writes only new rows, through the
functions the existing commands call. No migration. The API's description
did not change.

The five readings the build rests on (the phase log has each in full):
1. The wizard is the server's command line, not an app screen.
2. "Bike inventory" is the shop's customers' bikes, not parts stock.
3. A shop made by the wizard keeps the default owner number, as
   `shop profile init` does; who owns it is the `owner` role.
4. The terms are accepted only by the one owner at the keyboard, for
   themselves; never for staff or an absent owner.
5. A bike without a VIN is added again on every import of its file, and
   the report counts it.

```bash
bash <<'EOF4'
set -u
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
SHOP=""
ADDRESS=""
CITY=""
STATE=""
ZIP=""
PHONE=""
EMAIL=""
SRV=~/motodiag/server
DEV=~/Projects/moto-diag
LIVE=~/motodiag/live
case "$SHOP" in
  "") bad "put the new shop's name between the quotes on the SHOP= line, then paste this again; nothing was changed" ;;
  " "*|*" ") bad "the shop's name on the SHOP= line starts or ends with a space; take it out and paste this again; nothing was changed" ;;
  *[!0-9]*) ;;
  *) bad "the SHOP= line takes the shop's name, not a number; nothing was changed" ;;
esac
{ [ -x "$SRV/.venv/bin/motodiag" ] && [ -f "$LIVE/motodiag.db" ] && [ -x "$DEV/.venv/bin/python" ]; } || bad "this is not the computer the server runs on (run it on the home desktop, in the Ubuntu window); nothing was changed"
{ : </dev/tty; } 2>/dev/null || bad "this has to be pasted into a terminal window, where the setup can ask its questions; nothing was changed"
WANT=$("$SRV/.venv/bin/python" -c 'from motodiag.core.database import SCHEMA_VERSION; print(SCHEMA_VERSION)') || bad "the server's code could not say which database version it expects; nothing was changed"
read_live() {
  python3 -c '
import sqlite3, sys
db = sqlite3.connect("file:" + sys.argv[1] + "?mode=ro", uri=True)
version = db.execute("SELECT MAX(version) FROM schema_version").fetchone()[0]
bulletins = db.execute("SELECT COUNT(*) FROM technical_service_bulletins").fetchone()[0]
shop = db.execute("SELECT id FROM shops WHERE name = ? AND owner_user_id = 1", (sys.argv[2],)).fetchone()
print(version, bulletins, shop[0] if shop else "none")' "$LIVE/motodiag.db" "$SHOP"
}
FACTS=$(read_live) || bad "live could not be read; nothing was changed"
set -- $FACTS
[ "$WANT" = "$1" ] || bad "live's database is at version $1 and the server's code expects $WANT; nothing was changed, so bring this to the advisor"
[ "$2" -gt 0 ] || bad "live has no service bulletins, so the setup would load them into live as it starts; nothing was changed, so bring this to the advisor"
[ "$3" != 1 ] || bad "that name is the test shop set up while the app was tested, not a new shop; nothing was changed"
ID=$3
echo "Taking a backup of live first..."
(cd "$DEV" && .venv/bin/python -B .claude/skills/deploy/deploy.py backup first-shop </dev/null) || bad "the backup did not complete; nothing else was done"
export MOTODIAG_DB_PATH="$LIVE/motodiag.db" MOTODIAG_DATA_DIR="$LIVE"
if [ "$ID" = none ]; then
  ARGS=(--name "$SHOP")
  [ -z "$ADDRESS" ] || ARGS+=(--address "$ADDRESS")
  [ -z "$CITY" ] || ARGS+=(--city "$CITY")
  [ -z "$STATE" ] || ARGS+=(--state "$STATE")
  [ -z "$ZIP" ] || ARGS+=(--zip "$ZIP")
  [ -z "$PHONE" ] || ARGS+=(--phone "$PHONE")
  [ -z "$EMAIL" ] || ARGS+=(--email "$EMAIL")
  "$SRV/.venv/bin/motodiag" shop profile init "${ARGS[@]}" </dev/null || bad "the shop could not be registered (the lines above say why); the backup above is kept"
  FACTS=$(read_live) || bad "live could not be read after registering the shop; the backup above is kept"
  set -- $FACTS
  ID=$3
  case "$ID" in none|1) bad "the new shop is not on live after registering it; bring this to the advisor (the backup above is kept)" ;; esac
else
  echo "$SHOP is already on live (shop $ID), so the setup carries on where it stopped; the address lines are used only the first time."
fi
"$SRV/.venv/bin/motodiag" shop onboard run --shop "$ID" </dev/tty || bad "the setup stopped before its end (the lines above say why); the backup above is kept"
echo
echo "ALL GOOD"
EOF4
```

- After the backup, it registers the shop with `shop profile init`, with
  the address and the rest from six optional lines, unless the name is
  already registered.
- It gives the wizard the shop's id (`--shop`) and the terminal
  (`</dev/tty`).
- Before the backup, it refuses when live's bulletin table is empty
  (F292), and when there is no terminal to ask the questions on.
- It reads live read-only for the version, the bulletins and the shop,
  and again after registering the shop.
