## What shipped

- **Five server routes for a shop's card payments**, under
  `/v1/shop/{shop_id}/…`, in `src/motodiag/api/routes/payments.py`. Each
  needs the shop tier and an active membership, and calls the Phase 273
  functions as they are:
  - `GET …/payments/account` (`?refresh=true` asks Stripe first): the
    shop's Stripe account. Any member may read it.
  - `POST …/payments/connect`: makes the shop's Stripe account if it has
    none, and answers a one-use onboarding link. The owner only
    (`manage_billing`).
  - `POST …/invoices/{invoice_id}/payments/checkout`: a pay-link for the
    invoice.
  - `POST …/invoices/{invoice_id}/payments/terminal`: the invoice sent to
    the shop's card reader.
  - `GET …/invoices/{invoice_id}/payments`: the invoice's payments and
    their outcomes.

  The last three need `manage_shop` (the owner and the service writer).
  An invoice at another shop answers 404, as if it did not exist.
- **The invoice is still paid only by Stripe's news**, through the
  payments feed. Starting a payment never marks it paid. Nothing under
  `src/motodiag/payments/`, `src/motodiag/cli/` or `src/motodiag/billing/`
  changed.
- **Four error answers**, mapped in one place
  (`src/motodiag/api/errors.py`): a refused payment 409, Stripe not set
  up or a live key outside production 503, Stripe unreachable 503. No
  answer carries a key.
- **The API's description** lists the routes under a new `payments` tag,
  each with its 401, 402, 403, 404, 409 and 503 answers. The phone app's
  copy of it was refreshed on moto-diag-mobile's branch
  `phase-372-payment-api-routes-and-the-app` (`993fadc`) by the
  operator's desktop block.
- **Tests:** `tests/test_phase372_payment_routes.py` (26) and
  `tests/test_phase372_wiring.py` (18). All 26 route tests are red on
  master's code.
- **The guide:** `docs/guide/api.md` and a section "From the app" in
  `docs/guide/payments.md`. `README.md`'s route count now says 117, the
  measured count.
- **The prompt for the screens,**
  `docs/prompts/372_the_apps_payment_screens.txt`, written for option A
  and kept for 372B.

### Step 1: put the server on the new code

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Run it after the backend pull request is merged. It takes
about a minute, and asks for nothing.

What it does, in order:
1. **Checks before changing anything.** The server's copy of the code
   must be clean and on master, and GitHub's master must hold this phase.
2. **Brings the copy up to date** (fast-forward only).
3. **Restarts the server** and waits for it to answer healthy.
4. **Checks the server's description lists the five new routes.**

If the server does not come back healthy, the code is put back and the
server restarted on it. The payments feed is not restarted: its code did
not change.

```bash
bash <<'EOF2'
set -u
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
SRV=~/motodiag/server
API=motodiag-api.service
FIX=4e46bcf504156d6e8ef9520d115e6983bd056be5
for T in git systemctl sudo curl python3 sleep; do
  command -v "$T" >/dev/null 2>&1 || bad "this computer has no $T command; nothing was changed, so bring this to the advisor"
done
{ [ -d "$SRV/.git" ] && [ -f ~/motodiag/live/motodiag.db ]; } || bad "this is not the computer the server runs on (run it on the home desktop, in the Ubuntu window); nothing was changed"
[ "$(git -C "$SRV" branch --show-current </dev/null)" = master ] || bad "the server's copy of the code is not on master; nothing was changed, so bring this to the advisor"
[ -z "$(git -C "$SRV" status --porcelain --untracked-files=no </dev/null)" ] || bad "the server's copy of the code has changes made by hand; nothing was changed, so bring this to the advisor"
BEFORE=$(git -C "$SRV" rev-parse HEAD </dev/null)
git -C "$SRV" fetch -q origin +refs/heads/master:refs/remotes/origin/master </dev/null || bad "could not fetch from GitHub; nothing was changed"
TARGET=$(git -C "$SRV" rev-parse origin/master </dev/null)
git -C "$SRV" merge-base --is-ancestor "$FIX" "$TARGET" </dev/null || bad "master on GitHub does not have this phase yet: merge the pull request first, then paste this block again; nothing was changed"
git -C "$SRV" merge-base --is-ancestor "$BEFORE" "$TARGET" </dev/null || bad "the server's copy of the code has commits that are not on master; nothing was changed, so bring this to the advisor"
if [ "$BEFORE" != "$TARGET" ]; then
  echo "Bringing the server's copy of the code up to date..."
  git -C "$SRV" merge -q --ff-only "$TARGET" </dev/null || bad "could not bring the server's copy of the code up to date; nothing was changed"
fi
healthy() {
  for i in $(seq 30); do
    curl -s --max-time 5 http://127.0.0.1:8000/healthz </dev/null | grep -q '"status":"ok"' && return 0
    sleep 2
  done
  return 1
}
echo "Restarting the server (up to 60 seconds)..."
sudo -n systemctl restart "$API" </dev/null || { git -C "$SRV" reset -q --keep "$BEFORE" </dev/null; bad "could not restart the server; the code was put back as it was, so bring this to the advisor"; }
if ! healthy; then
  echo "The server did not come back healthy. Putting it back on the old code..."
  git -C "$SRV" reset -q --keep "$BEFORE" </dev/null
  sudo -n systemctl restart "$API" </dev/null
  healthy && bad "the server did not start on the new code; it is back on the old code and running, so bring this to the advisor"
  bad "the server did not start on the new code, and is not healthy on the old code either: bring this to the advisor now"
fi
FOUND=$(curl -s --max-time 10 http://127.0.0.1:8000/openapi.json </dev/null | python3 -c '
import json, sys
paths = json.load(sys.stdin)["paths"]
want = ["/v1/shop/{shop_id}/payments/account", "/v1/shop/{shop_id}/payments/connect",
        "/v1/shop/{shop_id}/invoices/{invoice_id}/payments/checkout",
        "/v1/shop/{shop_id}/invoices/{invoice_id}/payments/terminal",
        "/v1/shop/{shop_id}/invoices/{invoice_id}/payments"]
print(sum(1 for p in want if p in paths))') || bad "the server is healthy, but its description could not be read; bring this to the advisor"
[ "$FOUND" = 5 ] || bad "the server is healthy, but its description lists $FOUND of the 5 new payment routes; bring this to the advisor"
echo "The server's description lists the 5 new payment routes."
echo "The server is on: $(git -C "$SRV" log -1 --format='%h %s' </dev/null)"
echo "ALL GOOD"
EOF2
```
