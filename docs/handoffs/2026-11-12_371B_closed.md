### Step 1: put the fix on the server and restart the payments feed

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Run it after the pull request is merged. It takes about two
minutes.

What it does, in order:
1. **Checks before changing anything.** The server's copy of the code must
   be clean and on master, and GitHub's master must hold the fix with no
   newer code after it.
2. **Brings the copy up to date.**
3. **Sends one check-in with the new code.** Sentry must accept it before
   anything is restarted. If it does not, the code is put back.
4. **Restarts the payments feed.** It asks for the Ubuntu password once,
   restarts the feed and waits a minute.
5. **Reads the feed's own log.** The restarted feed must have started its
   alarm and logged no failed check-in.

If the feed does not run on the new code, the code is put back and the
feed is restarted on it. The server itself is not restarted, because it
does not use the changed code. Nothing the block prints contains a key.

### Step 3: test the alarm

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Run it after step 2's test email has arrived. It takes about 22
minutes.

What it does, in order:
1. **Checks first.** The payments feed must be running, asking Stripe,
   with its alarm on.
2. **Asks for the Ubuntu password once.**
3. **Sets a timer, then stops the feed.** The timer makes the computer
   start the feed again by itself in 20 minutes, even if the window is
   closed. Then the block stops the feed and counts down.
4. **Prints when to expect Sentry's email,** 10 to 17 minutes after the
   stop.
5. **Checks the feed is back.** After the feed starts again, the block
   checks it is asking Stripe properly.

This replaces 402's step 4 block, for two reasons:
- that block asks for the password again after 20 minutes, and Ubuntu
  usually forgets it after 15;
- it leaves the feed stopped if its window closes.

```bash

set -u
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
SRV=~/motodiag/server
ENVF=~/.config/motodiag/server.env

    del os.environ[k]

    line = raw.strip()

        continue

    if len(v) > 1 and v[0] == v[-1] and v[0] in "\"\x27":
        v = v[1:-1]

os.execv(cli, [cli, "payments", "feed", "status"])'

t = int(sys.argv[1])

    print(time.strftime("%Y-%m-%d %H:%M:%S %Z", time.localtime(t)) + time.strftime(" (%H:%M:%S UTC)", time.gmtime(t)))

    print(time.strftime("%H:%M %Z", time.localtime(t)))'

case "$SAYS" in *"Alarm: checks in to "*) ;; *) bad "the payments feed's alarm is off, so there is nothing to test; nothing was changed, so bring this to the advisor" ;; esac

echo "Your Ubuntu password, once (nothing has been changed yet):"
sudo -v </dev/null || bad "sudo did not take the password; nothing was changed"

TC=$(date +%s)

BACK_AT=$((TC + 1200))
trap 'echo; echo "SOMETHING IS OFF: you stopped this block before the end. The computer still starts the payments feed again by itself at $(when "$BACK_AT"); bring this to the advisor"; exit 1' INT

T0=$(date +%s)
systemctl is-active -q "$FEED" </dev/null && bad "the payments feed is still running after being stopped, so this test cannot run; bring this to the advisor"
echo
echo "The payments feed was stopped at $(when "$T0" full)."
echo "Sentry should email you about a missed check-in between about $(when $((T0 + 600))) and $(when $((T0 + 1020)))."
echo "The computer starts the payments feed again by itself at $(when "$BACK_AT"), even if this window is closed."
echo "Leave this window open and watch your email."

echo "The payments feed says:"

printf '%s\n' "$SAYS" | sed 's/^/    /'
[ "$RC" = 0 ] || bad "the payments feed is running again but is not asking Stripe properly yet (its lines above say why): bring this to the advisor now"

echo "The payments feed was stopped for $(( (T1 - T0) / 60 )) minutes. It is running again, and it asks Stripe for everything it missed."
```
