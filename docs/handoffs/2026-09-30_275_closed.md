confirmation is sent; which QuickBooks file. The third was sharper than
expected: Intuit's own page says QuickBooks Online's invoice import
refuses any company with sales tax set up. The operator's answer
(2026-09-29), verbatim:

> 1A, 2C, 3A, and the default for 4. For 3A, the export command says plainly when it writes the file that these are journal entries: they carry no line items and don't reach QuickBooks' sales-tax reports. The log records that neither file was tried in a real QuickBooks or Xero company.

**Neither export file was tried in a real QuickBooks or Xero company.**

- **Booking:**
  - a mechanic is never double-booked; an overlap with their bay work is
    a warning;
  - free slots come only from the shop's recorded hours (`hours_json`,
    `{"mon": "08:00-17:00", …}`) or `--open`/`--close`;
  - check-in opens (or links) the work order, and the appointment keeps
    the link.
- **Confirmation (2C):** `confirm` prints the text for staff to send
  themselves, sets `confirmed`, and logs an outbound contact. No
  notification event, no API change.
- **Calendar:** one calendar read live from appointments and bay slots;
  each event's UID names its row. Times are the shop's clock time (the
  shop records no time zone); a bay slot stored with a non-UTC offset is
  written in UTC.

  the shop's mapped accounts. The command prints: "These are journal
  entries, not invoices: they carry no line items, and they do not reach
  QuickBooks' sales-tax reports."
