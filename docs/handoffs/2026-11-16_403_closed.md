### Step 1 — the fleet's account may write to the phone app's repository

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Paste this whole block. It invites the fleet's account to the
phone app's repository with write access, accepts the invitation as the
fleet, and checks the fleet's key can now write there. If the last check
fails, the fleet's key is limited to one repository: open GitHub as the
fleet's account, Settings, Developer settings, its token, and add
moto-diag-mobile with "Contents: read and write"; then paste the block
again.

```bash
bash <<'EOF1'
set -u
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
ENVF=~/.config/motodiag/fleet-github.env
FLEET=$(grep '^FLEET_GITHUB_USER=' "$ENVF" | cut -d= -f2) || bad "no fleet account file"
[ -n "$FLEET" ] || bad "the fleet account file names no account"
gh api -X PUT "repos/Kubanjaze/moto-diag-mobile/collaborators/$FLEET" -f permission=push </dev/null >/dev/null \
  || bad "could not invite the fleet's account to moto-diag-mobile"
FT=$(grep '^FLEET_GITHUB_TOKEN=' "$ENVF" | cut -d= -f2)
INV=$(GH_TOKEN="$FT" gh api user/repository_invitations --jq '.[] | select(.repository.full_name=="Kubanjaze/moto-diag-mobile") | .id' </dev/null)
[ -z "$INV" ] || GH_TOKEN="$FT" gh api -X PATCH "user/repository_invitations/$INV" </dev/null >/dev/null \
  || bad "the fleet's account could not accept the invitation"
CAN=$(GH_TOKEN="$FT" gh api repos/Kubanjaze/moto-diag-mobile --jq .permissions.push </dev/null)
[ "$CAN" = "true" ] || bad "the fleet's key still cannot write to moto-diag-mobile (see the note above the block)"
echo "The fleet's account ($FLEET) can now write to moto-diag-mobile."
echo "ALL GOOD"
EOF1
```
