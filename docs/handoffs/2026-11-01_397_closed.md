## What shipped

- **(a) The one-second window.** Cause, as measured: the test gave its
  planted command one second to start a shell and print "started". Here
  that takes about 6 ms (86 ms at most beside 128 busy processes); in the
  Mac's full run at `ce97159` it took longer than a second, so nothing had
  been printed. With `sleep 2` planted before the print, the old test was
  red 10 of 10 with `assert 'started' in ''`, the Mac's failure exactly.
  `run_group` kept all that was printed; it was not the fault. Fix: the
  test tries windows of 1, 2, 4, 8, 16 and 32 s, stopping at the first in
  which the command reached its child; every window must end inside its
  bound (`window + 29` s); on that window "started" must be kept and the
  child must be dead. With `sleep 2` planted it is green (5 of 5, then 3 of
  3). `test_run_group_passes_a_run_that_ends` gets a 120 s window.
- **(b) A check that could not fail on a Mac.** `alive()` read `/proc`,
  which macOS lacks, so it called every process ended. It now asks `ps`,
  on both systems, and a new test gives it its own controls (this
  process alive; a zombie and a reaped child not). A child that escapes
  the kill turns the check red (mutation M4).
- **The census** (the command is in `397_step0.md`, S0-3): 19 lines in 9
  files. Two tests in this file fixed; three elsewhere (two in
