## What shipped

A shop can now answer "who did what, and when".

- **Migration 088** adds `audit_events`, with the index
  `idx_audit_events_shop` and two triggers that refuse any UPDATE or
  DELETE. Each row carries a hash chained to the row before it, so a change
  or a removal is found by `motodiag audit verify`.
- **One middleware** (`AuditMiddleware`, inside the rate limit) records
  every POST, PUT, PATCH and DELETE on the API: who (303's caller, the
  username at the time, the credential, the client address), what (method,
  path without its query string, handler, path ids, shop, status) and when.
  A failed audit write never fails the request; it is logged at ERROR.
- **The login** records the person who logged in.
- **`GET /v1/shop/{shop_id}/audit`**, for someone holding `manage_users`
  at that shop (today the owner), newest first, paged by `before_id`.
- **`motodiag audit list`, `verify` and `export FILE`.** Nothing is ever
  deleted and there is no expiry; `export` is the copy to keep.
- **The guides:** `docs/guide/api.md` (89 routes over 112 operations, the
  `audit` area) and `docs/guide/shop-workflow.md` ("See who did what").

### Step 1: put the server on the new code and see the first event

**Which computer:** the home desktop. **Which window:** the Ubuntu
terminal. Paste this whole block once 348 is merged to `master`. It asks
for nothing. It brings the server up to date and restarts it, makes one
deliberately wrong login (which the new activity log records, with no
password involved), then shows the newest entries in the log and checks
that the log is intact.

```bash
bash <<'EOF2'
set -u
SRV=~/motodiag/server
export MOTODIAG_DB_PATH=~/motodiag/live/motodiag.db
MD="$SRV/.venv/bin/motodiag"
bad() { echo; echo "SOMETHING IS OFF: $1"; exit 1; }
git -C "$SRV" fetch -q origin master </dev/null || bad "could not fetch from GitHub"
git -C "$SRV" checkout -q master </dev/null || bad "could not switch the server's copy to master"
git -C "$SRV" merge -q --ff-only origin/master </dev/null || bad "could not bring the server's copy up to date"
grep -q "class AuditMiddleware" "$SRV/src/motodiag/api/middleware.py" || bad "the server's copy does not have the activity log yet (is 348 merged?)"
sudo -n systemctl restart motodiag-api.service || bad "could not restart the server"
echo "Restarting the server (up to 60 seconds)..."
HEALTH=""
for i in $(seq 30); do HEALTH=$(curl -s --max-time 5 http://127.0.0.1:8000/healthz); echo "$HEALTH" | grep -q '"status":"ok"' && break; sleep 2; done
echo "$HEALTH" | grep -q '"status":"ok"' || bad "the server did not come back healthy (it said: $HEALTH)"
echo "$HEALTH" | grep -q '"schema_version":88' || bad "the server is up, but its database is not at the expected version (it said: $HEALTH)"
CODE=$(curl -s -o /dev/null -w '%{http_code}' -H 'Content-Type: application/json' \
  -d '{"username":"nobody-at-all","password":"not-a-password"}' http://127.0.0.1:8000/v1/auth/login)
echo "A wrong login answers: $CODE"
[ "$CODE" = "401" ] || bad "a wrong login should answer 401, it answered $CODE"
echo "The newest entries in the activity log:"
"$MD" audit list --limit 5 </dev/null || bad "could not read the activity log"
SEEN=$("$MD" audit list --path /v1/auth/login --limit 5 --json </dev/null | python3 -c "
import json, sys
print(sum(1 for r in json.load(sys.stdin) if r['path'] == '/v1/auth/login' and r['status'] == 401))") || bad "could not read the activity log"
[ "${SEEN:-0}" -ge 1 ] || bad "the wrong login was not written to the activity log"
"$MD" audit verify </dev/null || bad "the activity log's check did not pass"
echo "The server is on: $(git -C "$SRV" log -1 --oneline)"
echo "ALL GOOD"
EOF2
```
