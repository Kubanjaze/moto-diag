PART 2: the edit guard, as the operator worded it:
- It is a second PreToolUse hook on Bash in `.claude/settings.json`, beside the push guard.
- **Blocked:** `sed -i` in both its GNU and BSD forms (the operator's list names it without a path), and heredoc or redirect writes into `src/` or `tests/`: `>`, `>>`, `tee`, and `cat`/`printf`/`echo` into a file there.
- **Also covered, if the guard can see it:** a heredoc-fed script whose body writes into `src/` or `tests/`, which is 356's exact-match-script form. A form it cannot see, such as a script file run by name that writes there, is stated as a known limit, as 358 did.
- **Fail-closed, like the push guard:** a command the guard cannot parse, or an error inside the guard, blocks with a reason. It keeps its own time limit, well inside the hook timeout, because 358 measured that a timed-out hook does not block.
- **Positive controls:** a planted command for each blocked form is shown blocked.
- **Negative controls:** each of these is shown allowed, because a guard that blocks them breaks every session:
  - the commit-message heredoc (`git commit -F - <<'MSGEOF'`);
  - read-only heredoc scripts;
  - redirects into the session scratchpad and into `docs/`;
  - `sed -n`;
  - every other `git` command.
- The Edit and Write tools are not Bash and stay allowed.
- Write the known limits in the skill's CHANGELOG and in the phase log.
