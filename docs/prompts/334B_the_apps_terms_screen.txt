THE TWO SERVER ROUTES (../moto-diag/src/motodiag/api/routes/terms.py)

- GET /v1/terms
  Anyone may call it. Answers version, date, terms_url and privacy_url.
  With a credential it also answers accepted (true or false) and
  accepted_at (UTC, or null). For an anonymous caller both are null.
- POST /v1/terms/accept, body {"version": "<the version shown>"}
  Needs a credential. Records the caller's acceptance and answers version
  and accepted_at. A second call for the same version answers the first
  time. A version that is not the current one is 422, a ProblemDetail
  whose type ends "terms-version-stale": the text changed while the box
  was open, so read GET /v1/terms again and show the new version. This is
  not FastAPI's validation 422; src/api/errors.ts already tells the two
  shapes apart.

THE SWITCH ON THE SERVER

While the operator's MOTODIAG_TERMS_REQUIRED is on, every route that takes
a credential answers 403 with the problem type ending "terms-not-accepted"
until the caller's user has accepted the current version. Four routes
still answer: GET /v1/terms, POST /v1/terms/accept, GET /v1/auth/me and
POST /v1/auth/logout. Acceptance is per person: every user accepts for
themselves, and an owner's acceptance does not cover the staff. A new
version must be accepted again. The switch is off on the live server. The
operator turns it on after this phase and after Phase 293's new terms
version, so that every user accepts once (K128).
