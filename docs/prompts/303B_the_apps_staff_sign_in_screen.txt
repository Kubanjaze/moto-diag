HOW THE APP SIGNS IN TODAY

- The home screen (src/screens/HomeScreen.tsx) opens ApiKeyModal, and its
  handleSubmitKey stores the pasted key through ApiKeyProvider.setApiKey
  (src/contexts/ApiKeyProvider.tsx, the phone's Keychain), then calls
  resyncPushRegistration() (src/services/pushRegistration.ts).
- Its handleClearKey is today's sign-out: deregisterPushToken() first,
  while the credential still works, then clearApiKey().
- src/api/auth.ts sends the stored credential as the X-API-Key header. The
  server reads a session token from that header the same way it reads a
  key (../moto-diag/src/motodiag/auth/deps.py, get_api_key), so a session
  token can live in the same Keychain slot and go out the same way.

THE SERVER'S ROUTES (../moto-diag/src/motodiag/api/routes/auth.py)

- POST /v1/auth/login, body {"username", "password", "client"}. No
  credential needed. "client" is optional, at most 64 characters: send a
  short label for the phone, such as the app's name and platform. Answers
  token (it starts "mds_" and is shown only this once), expires_at (UTC),
  user (id, username, full_name, email) and memberships (each shop_id,
  shop_name, role, permissions). A wrong username or password is 401 with
  the problem type ending "login-failed". The server has no lockout or
  throttle on failed logins, so the screen shows none.
- GET /v1/auth/me. Answers user, memberships, credential (kind is
  "session" or "api_key", id, prefix) and tier.
- POST /v1/auth/logout. Ends the calling session: 204. For an API key it
  answers 400 with the problem type ending "not-a-session", so call it
  only for a session.
- A session lasts session_lifetime_days (30 by default). An expired or
  ended one no longer resolves, and every route that needs a credential
  answers 401 with the problem type ending "invalid-api-key".
