  node_modules/react-native-vision-camera/VisionCamera.podspec, lines 8 to
  14, sets `enableLocation = true` unless the Podfile defines
  `$VCEnableLocation`, and with it true the pod builds
  ios/Core/LocationProvider.swift, which uses CLLocationManager. ios/Podfile
  does not define it. No other library in package.json has iOS code naming
  CLLocationManager or CoreLocation.

  `$VCEnableLocation = false` in ios/Podfile, `pod install` prints
  "[VisionCamera] $VCEnableLocation is set to false!", drops
  VISION_CAMERA_ENABLE_LOCATION from the pod's build settings, and changes
  exactly two lines of ios/Podfile.lock: VisionCamera's checksum becomes
  b51af005669c6642dd1b4fca434eda4c1778de87, and PODFILE CHECKSUM becomes
  the SHA-1 of the new ios/Podfile's bytes. That second rule holds on main
  today: `shasum -a 1 ios/Podfile` prints
  1169a8abfdeab6189afb66ad97f52e71da16ab2a, which is the lock's PODFILE
  CHECKSUM.
- Android: android/app/src/main/AndroidManifest.xml declares
  ACCESS_FINE_LOCATION with android:maxSdkVersion="30" (lines 23 and 24),
  for Bluetooth scans on Android 11 and older; BLUETOOTH_SCAN carries
  neverForLocation. But two libraries' own manifests declare location with

  ACCESS_FINE_LOCATION) and react-native-bluetooth-classic

  react-native-vision-camera's Android manifest asks for no location.
- The build number: ios/MotoDiag.xcodeproj/project.pbxproj sets
