## Goal

Every row a first shop needs is ✅ on master: 303 (staff logins), 330 (the setup wizard), 334 (the terms), 343 (crash reports and the alarm), 345 (the nightly backup), 348 (the audit log), 371 and 372 (the payments feed and the payment routes), 402 (share links off, the return page), 404 (the plans' limits), 405 (the deploy check) and 293 (the manual library, with terms 1.1) here; 303B, 334B and 372B in the app (rows 303B, 334B and 372B of this repository's `docs/ROADMAP.md`, at its lines 560, 606 and 653, each ✅ CLOSED 2026-11-22 and naming the app's merges `2f6739c`, `58142e4` and `f87d04b`). Each was proven on its own. Nothing yet proves them together: the Step 0 census found no test and no module that walks a shop's day end to end (`Launch readiness` 0 in `src/` and `tests/`), and the only launch material is a checklist (`docs/launch-checklist.md`, whose status line still says "Phase 210 is still deliberately unstarted") and 209B's reachability audit. The Step 0 report classified the phase an extension, and this plan agrees: it adds to what exists and changes what no current code does.

After this phase:

1. **One test file walks the first shop's day through the API** on a fresh database at the code's schema (92), with the terms switch on as it will be at launch, and asserts at each step what the shop would see. It needs no network and no model, so it runs inside the fleet's fence and in every regression after it. If a later change breaks the way two rows fit together, this test goes red.
2. **One read-only launch check, `motodiag launch check`,** runs on the server, reads live and the server's settings, prints each launch condition as ready or not, prints no key or secret, writes nothing (it opens live without `init_db`, F292), and exits 0 only when every condition is ready, ending with ALL GOOD. Its conditions are the scope's, in order: the schema at the code's version; the server in prod with Stripe live and the real tier prices; the payments feed and Sentry's alarm checking in; last night's backup; the terms switch on, at version 1.1; a reviewer set; the test shop inactive (K124); the home desktop's free disk above the floor 390 set.
3. **The handoff carries the operator's live steps, in the scope's order,** each a paste block tested against a stand-in before it is handed over: the server on the merged code; Stripe live checked (it has been on since 2026-11-11, see Logic); the app on the shop's phones through TestFlight (K136); the terms switch on, then 334B's phone check; the test shop marked inactive (K124, the advisor's block); the launch check printing ALL GOOD; then the onboarding day with 330's corrected first-shop block, and the owner taking the Shop plan on live from 372B's plan screen before the shop's first day, since every shop route answers 402 until then.

**What the operator's answers settle (K136, 2026-11-24).** (1) The fleet stops before each live step: this build ends at the close-out, and every live step is the operator's, from the handoff. (2) The app reaches the first shop's phones through TestFlight; the App Store waits for a public API (K137); installing from the Mac ends with this phase. (3) No private network as the product; for shop one only, the phones join Tailscale as a stopgap (K74); the shop's staff who get the app are one owner and two to five mechanics, which on the server are the `owner` role and the `tech` role. (4) The shop pays Mekno first; the shop's customers paying by card comes later. So the end-to-end test proves both paths on a fresh database (the rows are ✅ and the app's screens exist), the shop's own Shop plan is the first thing the day records after the wizard, and the live steps for shop one need no Connect onboarding of the shop's own Stripe account.

**Why the launch check is a command and not a test.** 244H (`tests/conftest.py`, the redirect and the tripwire) forbids any test from reading live, and the Step 0 report says the same: the check must read live data, so it is a tool that is run, and its tests run it against stand-in databases and settings only.

**Why nothing under `src/` changes but the new command and two wiring lines.** The scope says this phase builds nothing new for shops, and the Step 0 report supports one addition to `src/`: the launch check. Every route, command, role, limit, switch default and rule this phase touches is used as it is. A step of the day that cannot be walked without changing an existing route or rule is a stop (Rule-1 stops anticipated), not a change.
