## S0-2. (b) `alive()` cannot fail on a Mac

A child that escapes the kill (bash job control, `set -m`, puts it in a
process group of its own, so `killpg` misses it) is alive one second after
`run_group` returns (`397_measure.py alive`):

    pid 3925499: the test's alive() says True; with /proc absent (macOS) it says False

The second answer is the test's own `alive()` with `/proc` read from a
folder that does not exist, as on macOS: `os.kill(pid, 0)` succeeds, then
`/proc/<pid>/stat` does not exist, so it returns False for a live
process. The check `assert not alive(pid)` passes on the Mac whatever
happened to the child.

`ps -o stat= -p <pid>` answers on both systems: procps-ng 4.0.4 here, and
BSD `ps` on macOS. It prints the process's state (`Z` for a zombie) and
exits 0, or prints nothing and exits 1 when there is no such process. The
fence binds `/usr` and gives a private `/proc` (`fence.sh` line 108–110),
so `/usr/bin/ps` answers inside it too.

## S0-4. The design, and why it is not a weaker assertion

**(a)** The test runs the planted command in windows of 1, 2, 4, 8, 16
and 32 s, each in its own folder, stopping at the first window in which
the command reached its child: the pid file holds a whole line, which it
writes only after `echo started`. Every window must end inside its bound,
`window + 29` s (the old bound was 30 s for a 1 s window). On the window
that counts, "started" must be in what `run_group` kept, and the child
must be dead. If no window up to 32 s gets that far, the test fails and
says so.

A longer window is the operator's "fine". On an ordinary machine the test
still takes one window of 1 s. Each of the three proofs is asserted as
strongly as before:
- the whole group is killed: the child is checked on the window that
  reached it, with an `alive()` that now answers on both systems;
- what was printed is kept: on that window, "started" was printed before
  the pid file was written, so it must be in what `run_group` kept;
- the run ends inside its bound: asserted on every window, with the old
  slack.

`test_run_group_passes_a_run_that_ends` gets a 120 s window: the run ends
at once, so the window costs nothing and only a stalled machine reaches
it.

**(b)** `alive()` asks `ps -o stat= -p <pid>`: alive if `ps` names a state
that is not `Z`; ended if it prints nothing and exits 1; any other answer
fails the test rather than reading as "ended". A new test gives `alive()`
its own controls on both systems: this process is alive; a child that has
exited and not been reaped (a zombie) is not; a reaped child is not.

**Mutations** (`397_mutate.py`, Linux and macOS): what was printed lost;
only the direct child killed; the run outliving its bound; a child that
escapes the group (b's known-bad); `alive()` answering "ended" without
asking; a zombie counted alive; the windows not widening and the window
check skipped, each with `sleep 2` planted. And the known-bad that must
stay green: `sleep 2` before `echo started`. It also runs master's
`ce97159`-era file on the two known-bad cases, so the Mac can see the old
test red on `sleep 2` and green on an escaped child.
