## S0-1. How a stage dies today

The service (`/etc/systemd/system/motodiag-fleet.service`, read with
`systemctl show`): `KillMode=control-group`, `KillSignal=15`,
`TimeoutStopUSec=1min 30s`, `Restart=always`. A `systemctl restart`, a
`wsl --shutdown`, a power cut or a crash all end the same way for the
fleet: every process in the unit's cgroup dies (the dispatcher, `fence.sh`,
`bwrap`, `claude`, a model-free pytest). Python's default SIGTERM action
ends the dispatcher without running `finally` or `except` blocks, so
**nothing can be written at the moment of death**: whatever a resume needs
must be on disk before the step that may be killed.

No process outlives the restart (control-group kill), so after a start "a
run directory with no live process" is every run directory the previous
process left unfinished. A record that names a PID must also name the boot
(`/proc/sys/kernel/random/boot_id`), since a PID is reused after a reboot.

## S0-2. Every kill point, and what each leaves behind

Line numbers are `dispatcher.py` at `6f32013`. "Due" is `due_for`
(l. 521): a stage runs when its label's last `labeled` event is newer than
the rank's last marker. A run directory is `runs/<stamp>_<rank>_<phase>/`
with `clone/` (the stage's clone) and `run/` (the fence's `/fleet/run`:
`claude/`, `home/`, `tmp/`, and the Engineer's `session.json`,
`session.err`, `engineer.json`). A model-free run makes its own
`runs/<stamp>_check/`.

**What a killed model call leaves.** A `claude -p` that is killed prints
nothing: its session id is only in the final JSON. It is on disk as the
transcript's file name, `run/claude/projects/-fleet-moto-diag/<id>.jsonl`
(the fence sets `CLAUDE_CONFIG_DIR=/fleet/run/claude`, `fence.sh` l. 146).
Seen on F219's own run: `runs/20261025_150624_engineer_389A/run/claude/
projects/-fleet-moto-diag/b021b077-0768-4f3a-9e54-bcf35186cbb1.jsonl`. A
call killed before its first turn leaves no transcript: there is no
session to resume, and the call is made again in the same run directory.

### The resume itself (389's code)

`cycle` pops `paused` from `state.json` and saves **before** running the
resumed stage (l. 1116–1117). A kill during a resumed stage loses the

### The model-free runs

`check_run` (l. 631) is called by the push gate (fast), by the Engineer
(full: `wholetree.sh --full` then `regression.sh`) and by the Red Team (F9).
Nothing links a stage to its `check` dir, and nothing reads a killed one
back. Rerunning on the same commit is always correct: the run is a pure
function of the commit (no model, no token, no network, `--net none`).

### `prune_runs` (l. 609)

Keeps the newest 20 run dirs by name (`KEEP_RUNS = 20`, `dispatcher.py` l. 99), plus the paused run. Each stage makes
one to three (its own and its checks), so an unfinished run is pruned after
seven to twenty later stages. Nothing marks a run as unfinished.

## S0-3. What 389's resume code gives, and what it lacks

Reused as it stands:
- `FencedRunner(resume=session)` (l. 276–371): `--resume <id>` prepended to
  every `claude` call and to the Engineer's watched session; a resumed call
  skips the 70% gates (`gate_model`, l. 307); a usage limit inside a
  resumed call is still caught (`RateLimited`).
- Every `stage_*` takes `resume=` and then reuses the run directory and its
  clone instead of making new ones (l. 693, 722, 757, 799, 886, 933, 960).
- `Fleet.resume(record)` (l. 1002): dispatch by `stage` to the right
  `stage_*` with the record's arguments. The pause record (`grep -n 'self.pause(' dispatcher.py`: l. 705, 740,
  774, 820, 897, 946, 971) already carries every argument a stage needs.
- The Engineer's continuation prompt on resume (l. 813–815).
- `pause`'s stop comment, the shape for "could not resume" (l. 1122).

Missing, and what this phase adds:
1. **A record written before the stage starts.** The pause record exists
   only after a usage limit. F219's own words: "records the stage it is
   running … before it starts (the same record a pause writes), clears it
   when the stage ends".
2. **The session id of a killed call**: from the transcript's file name,
   not from `claude`'s output (S0-2).
3. **Steps, not just the stage.** Today a `resume=` stage reruns from its
   model call. F219's stage had finished its session; it needs the
   model-free run again, then the push, then the PR, then the marker, then
   the label. Each later step writes to GitHub, and a kill can fall between
   the write and the record of it, so a resumed step checks GitHub first
   (is the branch at this commit, is this marker there, is this label on)
   and does only what is missing.
4. **The search on start**, before the first cycle, over both sources:
   the run directories' records, and the issues' rank markers.
5. **`paused` kept until the resumed stage ends** (l. 1116).
6. **`prune_runs` skips an unfinished run.**
