The verbs the scope gives it are: (1) prove a first paying shop's working day end to end on a fresh database, through the API (nothing yet; no test file exists). (2) Run a read-only launch check that says on live whether launch can happen and prints ALL GOOD or not (nothing yet; no check exists in src or tests). (3) Turn Stripe to live, put the app on the shop's phones, switch the terms gate on, and mark the test shop inactive (operator steps outside the repository; none is reachable from code yet). ## Risks and stops

Rule 1 reserves these for the operator, and the scope names them, so the phase must stop before each: the terms switch going on (a live behaviour change for every user, K128 and K134); marking the test shop inactive (a live-database change); Stripe live (a credential and an outside account); and the app on the shops' phones. The mission's 'needs the operator: nothing' disagrees with K134, which names those steps; record the disagreement in the phase log and ask the operator to confirm which reading the plan takes. The launch check must read live data, and the no-test-reads-live rule (244H) applies to tests only, so keep the check a tool that is run, not a test. The end-to-end test must run only on a fresh database. Dependence on app rows that this census did not confirm is a risk to the whole phase. Nothing here is a real fork between two shipped designs, and the scope itself changes no threshold or rule definition.
