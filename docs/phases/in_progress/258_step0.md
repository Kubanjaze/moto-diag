## S0-3 — the Fiddle 50 resolves transmission `unknown`

`TRANSMISSION_LOOKUP`'s SYM Fiddle entry (`_E("SYM", "Fiddle III", CVT,
("fiddle", "fiddle iii", "fiddle 3", "fiddle3"))`) carries no "fiddle 50"
spelling, but the corpus's own 354 and 353 rows name the machine "Fiddle
50" (354's own tier-0 test list names it). Measured: a (SYM, Fiddle 50)
query resolves provenance `unknown`, and `rows_for_machine` **withholds 8
rows** — every transmission-scoped CVT row — so a Fiddle 50 owner
reporting belt squeal reaches none of 254's roller/belt/clutch content;
only the two unscoped rows survive. The withheld count is recorded in
`retrieval_withheld`.

## S0-4 — the Vespa LX 50's tier-0 carb row is displaced by the symptom

With no symptoms, the LX 50 prompt holds all three layers (CVT 8, ELEC 1,
CARB 1). With the belt-squeal symptom, the carb row is gone (CVT 10, ELEC
1, CARB 0) and two **tier-2** rows take its place. Cause, measured:
`relevance_tokens("scooter jerks at low speed, belt squeal, won't pull
away")` = `{away, belt, jerks, pull, scooter, speed, squeal}`; the carb
row's title — "Vespa's **small carburetted scooters**: Dell'Orto on the
two-stroke 50s…" — scores **0** (no plural stemming: "scooter" ≠
"scooters"), while a tier-2 CVT row sharing the word "belt" scores 1 and
wins a reserved slot. The rider's symptom is about the CVT, so relevance
choosing CVT rows is by design (250B); scoring the machine's own carb row
0 against a symptom that says "scooter" is a tokenisation miss, and tier-2
rows displacing a tier-0 row is the measured cost.

## S0-5 — the Zuma 125: a tier-0 electrical row exists and is crowded out

`(Yamaha, Zuma 125)` holds 15 tier-0 pairs including 354's YW125 row —
no year window. But the Zuma 125's prompt (12-row cap) under a belt
symptom holds CVT 8 and **no electrical row**: rank order within tier 0
(severity, title) puts five other tier-0 rows ahead of it. With a charging
symptom ("battery not charging, lights dim at idle") the relevance reserve
brings it in: ELEC 1. Composition working as designed, measured in both
directions.

## S0-6 — the year window on the Ruckus carb row (F132's rule)

A 2015 Ruckus reaches 353's carb row at tier 0 (in the 2012–2025 window);
a 2008 Ruckus does not — the row is year-filtered out, and the 2008 prompt
holds no layer row at all without symptoms (CVT 4 only arrive when the
symptom pushes tier-2 rows in). The gate tests inside the window and
states the outside-window gap rather than finding it.

## S0-7 — the Metropolitan 2005 misses the CHF50 rows under its own name

The 2002–2006 Metropolitan **is** a CHF50 (352/354's own finding; F152's
cover). But the CHF50 carb and electrical rows are modelled `CHF50` only:
`(Honda, Metropolitan)` holds 0 pairs on those rows, and a 2005
Metropolitan query reaches none of them — while the CVT multi-make rows,
which do list "Honda Metropolitan", reach tier 0. A 2005 Metropolitan
owner gets CVT recall rows at tier 0 and the F149 unverified charging rows
at tier 1, but not the carburettor or charging rows written for the
machine they own. The current injected NCW50 Metropolitan correctly stays
out (354's modelling); the 2005 case is the gap.

## S0-9 — the doors the row's query can arrive through

- **CLI** (real root): `kb search` reaches every layer term measured —
  254's own vocabulary ("variator", "weight roller", "clutch bell",
  "driven pulley", "primary sheave", "drive belt width"), 354's
  ("stator resistance", "regulator rectifier"), 353's ("pilot screw",
  "auto by-starter"). `kb list --make Kymco` returns the make's rows with
  labels. `kb by-code "2"` reaches only blink-code rows of other makes;
  **no scooter row carries a DTC code** (measured over the whole corpus).
- **`motodiag code 2`** classifies as "Honda blink code, Make: Generic
  (all makes)" — the generic classifier answers; no scooter make has a
  `seed/dtc_codes/` file (the directory holds aprilia, bmw, ducati,
  generic, harley_davidson, ktm, mv_agusta, triumph only).
- **API**: `GET /v1/kb/issues?make=Kymco` → 18 rows; `GET
  /v1/kb/search?q=variator` → 7. The doors agree with the CLI modulo the
  resolver asymmetry F97 already records.
- **Adapters**: `hardware compat recommend` answers "No compat entries
  known for this bike" for every scooter machine measured — Ruckus,
  CHF50, Agility 50, Jet Euro 50, Fly 50, LX 50, Zuma 125, Buddy 125.
  `compat_matrix.json` holds eleven makes, none of them Kymco, SYM,
  Piaggio, Vespa or Genuine, and no Honda row names a scooter.

## S0-10 — the axis holds for machines the content is not for

A Grom 125 (manual) query withholds all 8 transmission-scoped CVT rows
(provenance `manual`) and reaches 8 Grom-specific tier-0 rows; a
CBR1000RR query reaches none of the three layers at tier 0 or 1. The two
**unscoped** CVT rows (the naming row, the recall-index row) reach manual
bikes at tier 2 under belt-shaped symptoms — by design, their scope is
the search term; pinned so the day someone scopes them the gate notices.
Tier-0 integrity: every tier-0 pair of every gate machine belongs to a row
that names the machine (measured; the apparent misses are spelling
variants — "Honda PCX150" vs "PCX 150" — which the junction handles).
F142's cross-make pairs exist in the junction (e.g. `(Kymco, Jet 14)`,
`(SYM, X-Town 300)`) and none touches a gate machine's tier 0.

## S0-11 — what this sandbox changes
