## Risks and stops

Stop for the operator (rule 1, a real fork): whether a link minted before the switch is set false still opens. The prompt leaves this to Step 0, but the two choices ship different things. (a) Refuse every link while switched off, which matches K74's words "customer share links are switched off". (b) Keep old links opening and refuse only new mints. The Science Officer recommends (a), because a link that still opens after the switch leaves the public path open. The operator picks.

Rule 1 scope, not a stop now: the start-up change is approved by K74 only for share links switched off. With the switch on, the check must stand exactly as it is. Any other change to the check's definition is a stop.

Step 0 work, not a stop: name the open route from the code. The OpenAPI snapshot gate: if the share route's documented responses change, moto-diag-mobile's snapshot must be refreshed in a session rooted there. Name it at Step 0. The app's own handling of the refusal is outside this phase.

Not a stop: no live-database change, no credential and no login is named in this phase. The server.env values are the operator's to write. No test is known to be unable to go green; this is unverified until the suites run.
