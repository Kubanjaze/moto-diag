# Phase 343 — Telemetry + crash reporting (Sentry)

**Version:** 1.0 | **Tier:** Standard | **Date:** 2026-11-01

---

## Goal

When the live API on the home desktop fails, nobody is told. `src/motodiag/api/errors.py`'s last-resort handler (`_unhandled_handler`) writes the stack trace to the journal and answers a bare 500, and that journal is read only when someone logs in to look. A mechanic who hits a crash at the bench sees "Internal server error" and the operator learns of it, if at all, when the shop phones. Step 0's census (run on this branch from `15e55c3`) found nothing to extend: 0 hits for `sentry_sdk`, `SENTRY_DSN`, `capture_exception`, `traces_sample_rate` and `init_sentry` in `src/`, `tests/`, `.claude/`, `docs/` and the mobile app's `src/`; the one `sentry` hit in `tests/` is the letters inside `TestEveryCanonicalNameResolvesToItsEntry` (`tests/test_phase379_lookup_and_relevance.py:27`). The hits Step 0 left unread were read for this plan: `rg -n -i telemetry src` finds the OBD adapter failure reports (`obd_reports/`, `api/routes/diagnostics.py`, `push/events.py`'s maintainer alert), the audio sweep's per-call counters and the predictor's "telemetry, not scoring" comment, none of which captures an exception or measures a request; `rg -n -i crash src` is 153 hits in 55 files, 128 of them in the knowledge corpus (a crashed bike) and the rest the ECU crash-recovery scenario, the recorder and the safety rules. So this is greenfield, as Step 0 classified it, and no existing path is duplicated or altered beyond the two seams named in Logic item 5.

What exists to hang it on: every request already carries an id (`RequestIdMiddleware`, `request.state.request_id`, echoed as `X-Request-ID`), every request's duration is already measured (`AccessLogMiddleware`), `Settings` (`src/motodiag/core/config.py`) reads `MOTODIAG_`-prefixed names, and the live unit (`ops/desktop/motodiag-api.service`) already loads `~/.config/motodiag/server.env` (mode 600) through `EnvironmentFile`, the file the unit's own comment names as where "keys the operator adds go". `motodiag serve` runs uvicorn with `factory=True`, so `create_app()` runs in each worker and a per-app sender is a per-worker sender.

This phase ships the row's four promises as far as a backend can, and takes the rest to the operator at one stop:

- **Sentry integration.** A small client of Sentry's envelope protocol, in the standard library, turned on by one line in `server.env` (`MOTODIAG_SENTRY_DSN=`) and inert without it. The DSN lives only on the desktop, in that file, under the K62 pattern Phase 345 set for an outside account's key: never in the repository, a log, an issue, a chat or the fleet's fence.
- **Crash reports.** Every unhandled exception the API answers with a 500 becomes one event: the exception's type, its message with session tokens redacted, the stack frames, the request id, the method, the route template and the release. Nothing else: no headers, bodies, query strings, local variables, user or customer. The exact rule is the operator's to confirm at the stop (part (d)); the plan carries the Captain's recommendation.
- **Performance monitoring.** One transaction per sampled request: the route template, the method, the status and the duration. The sample rate is a threshold and so the operator's (part (e)).
- **User session replay.** A replay records what is on a mechanic's screen, and that screen holds customer names and vehicle owners. There is no screen on the backend, no crash SDK in the phone's binary, and the launch checklist's privacy answers rest on there being none. Whether replay ships at all, and masked how, is a real fork and the operator's (part (c)). The Captain's recommendation is that it does not ship in this phase.

What the operator gets: a Sentry dashboard that shows each crash within seconds, with the request id that the mechanic's error screen can be matched to, and one command (`motodiag telemetry check`) that proves the wire is up.

   (d) **What an event carries, the scrubbing rule.** Recommended, and written into item 3 as the rule: the exception's type; its message, with every `mds_` session token replaced (the `SESSION_TOKEN_RE` pattern of `src/motodiag/cli/serve.py`, which Phase 303 wrote for the same reason) and cut to 500 characters; the stack frames as file, function, line number and an in-app flag, with no local variables and no source lines; the request id; the method; the route template (`/v1/shop/{shop_id}/work-orders/{wo_id}`, never the path with the ids in it); the response status; the release (`motodiag.__version__`); the environment; the host name. A transaction carries the same route template, method, status and the two timestamps. The operator may narrow or widen this; the Engineer applies the words.
   (e) **The numbers.** Recommended: transactions sampled at 0.1 (one request in ten; errors are never sampled, every one is sent); a send queue of 100 events per worker, beyond which an event is dropped and counted rather than making a request wait; a 5-second transport timeout; a flush of 2 seconds at process exit. 2. **`src/motodiag/telemetry/__init__.py` and `src/motodiag/telemetry/dsn.py`** (new), and three fields on `Settings` in `src/motodiag/core/config.py`. `parse_dsn(text) -> Dsn` reads `https://<public key>@<host>[:port]/[<path>/]<project id>` into scheme, host, port, public key, project id and path prefix; `Dsn.envelope_url` is `<scheme>://<host>[:port]/<path>api/<project id>/envelope/` and `Dsn.auth_header` is `Sentry sentry_version=7, sentry_client=motodiag/<version>, sentry_key=<public key>`, the two things Sentry's developer documentation asks a client to send. It refuses a DSN with no key, no host or no project id, naming only what is missing and never echoing the text. `Dsn.__repr__` and `__str__` show the host and project id only, so no traceback, log line or `motodiag config` output can carry the key. The three settings, read from the environment with the `MOTODIAG_` prefix like every other: `sentry_dsn: str = ""` (empty means off); `telemetry_traces_sample_rate: float`, defaulting to part (e)'s value, with a validator that refuses anything outside 0.0 to 1.0 the way `ai_temperature` is bounded; `telemetry_environment: str = ""`, which falls back to `env.value` when empty. No new dependency and no new extra: `pyproject.toml` is unchanged.
   Finish line: the example DSN from Sentry's documentation (`https://examplePublicKey@o0.ingest.sentry.io/0`) parses to its host, key and project id and its envelope URL ends `/api/0/envelope/`; a DSN missing its key, and one missing its project id, are each refused naming the missing part, and a planted key value appears nowhere in the refusal; the repr of a parsed DSN holds no key, with the control that the same assertion goes red when the key is printed on purpose; a sample rate of 1.5 is refused and 0.0 and 1.0 are read; an empty `MOTODIAG_SENTRY_DSN` gives settings that say off.

3. **`src/motodiag/telemetry/events.py`** (new): what an event is, as part (d) decides. `redact(text) -> str` applies `SESSION_TOKEN_RE` and the 500-character cut. `error_event(exc, *, request_id, method, route, status, release, environment, server_name, clock=None) -> dict` builds one Sentry event: `event_id` (32 lowercase hex from `uuid4`), `timestamp` (from `motodiag.core.timestamps.utc_now()` or the injected `clock`; no private `_now` helper, so `PRIVATE_HELPERS` stays at 19), `platform` "python", `level` "error", `logger` "motodiag.api", `release`, `environment`, `server_name`, `sdk` (`motodiag.telemetry` and the version), `tags` (request id, route, method, status), `request` (`method` and `url` set to the route template), and `exception.values[0]` with `type`, the redacted `value`, and `stacktrace.frames` from `traceback.extract_tb(exc.__traceback__)`: `filename` (relative to the package when the frame is under `motodiag`), `function`, `lineno`, `in_app` true for the package's own frames. The function takes no request, header, body or query string, so none can reach an event; that signature is the rule. `transaction_event(*, route, method, status, started, ended, request_id, release, environment, server_name) -> dict` builds one transaction: `type` "transaction", `transaction` "<METHOD> <route>", `start_timestamp`, `timestamp`, `contexts.trace` with a 32-hex `trace_id`, a 16-hex `span_id`, `op` "http.server" and a `status` of "ok" below 500 and "internal_error" from 500, `spans` empty, and the same `tags`. `message_event(text, **same)` builds the one event `motodiag telemetry check` sends. Every function is under McCabe 20, so `COMPLEX_FUNCTIONS` stays at 25.
   Finish line: an event built from an exception raised inside a planted function carries that function's name and line in a frame marked in-app, with no `vars` key and no `context_line` in any frame; a message holding a planted `mds_` token appears redacted, with the control that the assertion goes red when `redact` is skipped; a 2,000-character message is cut to 500; the `request.url` is the route template passed in and a path with a numeric id passed as the route is a test failure (the test passes a template and asserts no digit run of the id's length); `inspect.signature(error_event)` names no parameter called `request`, `headers`, `body` or `query`; a transaction's `status` is "ok" at 200 and "internal_error" at 500 and its two timestamps are the injected ones.

4. **`src/motodiag/telemetry/envelope.py` and `src/motodiag/telemetry/sender.py`** (new): the wire and the thread. `envelope(event, dsn, sent_at) -> bytes` writes Sentry's envelope: one JSON header line (`event_id`, `sent_at`, `dsn`), one JSON item-header line (`type` "event" or "transaction" by the event's own `type`, `length` in bytes) and the JSON payload, each line newline-terminated, UTF-8. `Sender(dsn, *, transport=urllib_transport, queue_size, timeout_s, clock=None)` has `enabled` True, `capture(event) -> bool` (`put_nowait` on a `queue.Queue(maxsize=queue_size)`; False and `dropped += 1` when full; never blocks, never raises), a daemon thread that takes one event at a time and posts its envelope to `dsn.envelope_url` with `Content-Type: application/x-sentry-envelope` and `X-Sentry-Auth: <dsn.auth_header>`, `flush(timeout_s) -> bool` (True when the queue drained in time), and `close()` (flush, then stop the thread), registered with `atexit` for part (e)'s 2 seconds. A non-2xx status is logged at WARNING at most once a minute, naming the status and the host and never the key; a 429 with `Retry-After` pauses sends for that many seconds (at most 60), dropping and counting meanwhile; a transport that raises (refused connection, timeout) is logged the same way and breaks nothing. The `transport` is one callable, `(url, headers, body) -> (status, reason_text)`; the default uses `urllib.request` with part (e)'s timeout, and tests pass an in-process fake, so no test opens a socket (`tests/support/network_guard.py` refuses anything but loopback, and the fence runs with no network). `NullSender` has `enabled` False, `capture` returning False, `flush` returning True and no thread; `make_sender(settings)` returns it when `sentry_dsn` is empty, and never logs or raises on a bad DSN at import time: a bad DSN is logged once at ERROR, naming what is missing, and gives a `NullSender`, because a typo in `server.env` must not stop the API (the way `_unhandled_handler` and `notify_obd_failure` already put the product before the report). No `except Exception: pass` anywhere: every handler logs, so `SWALLOWED_EXCEPTIONS` stays at 22.
   Finish line: an envelope's three lines parse back and the item header's `length` equals the payload's byte length, with a control that a payload holding a non-ASCII character still matches; the fake transport receives the auth header carrying the key and the envelope content type; a 429 with `Retry-After: 3` from the fake raises nothing, pauses sends and the next capture inside the pause is dropped and counted, with the control that a capture after the injected clock passes 3 seconds is sent; with a transport that blocks on a threading event, 150 captures through a queue of 100 return within 100 ms measured on the caller's thread and `dropped` is 50; `flush` returns True once the fake has received every envelope and False when the transport is held; a transport that raises `OSError` breaks no caller and is logged once; `NullSender` starts no thread (`threading.active_count()` unchanged); the default `urllib_transport` round-trips against an HTTP server on 127.0.0.1, as 345's did.

5. **`src/motodiag/api/telemetry.py`** (new) and two seams in existing code. `install_telemetry(app, settings, *, sender=None, sample=None)` builds the sender from the settings (or takes the one passed, for tests), stores it at `app.state.telemetry`, and adds `TelemetryMiddleware`: it reads `request.state.request_id`, times the request as `AccessLogMiddleware` does, finds the route template from `request.scope["route"].path` when a route matched (else "unmatched"), skips `/healthz` entirely, and, when `sample()` (by default `random.random() < telemetry_traces_sample_rate`) says so, captures one transaction. The middleware is added after `RequestIdMiddleware` in `create_app()`, so it runs inside it and the id exists, and it never changes a response. The first seam: `create_app()` calls `install_telemetry(app, app_settings)` after `register_exception_handlers`, and its startup log line gains `telemetry=on <host>/<project id>` or `telemetry=off`. The second seam: `_unhandled_handler` in `src/motodiag/api/errors.py` gains three lines after its existing `logger.exception`: fetch `request.app.state.telemetry` (a missing attribute means no sender and no capture, so an app built without `install_telemetry` behaves as today), build `error_event` with the request id, method, route template and 500, and `capture` it. The log line and the bare RFC 7807 body are unchanged. Only the unhandled path captures: a mapped domain error (`ReportBuildError` 500, `BillingProviderError` 502, every 4xx) is the product answering, not crashing, and sends nothing; a request-validation 422 sends nothing.
   Finish line: with a fake sender passed to `create_app` through `install_telemetry`, a test route that raises `RuntimeError` reaches the sender with exactly one error event whose `tags.request_id` equals the response's `X-Request-ID` header and whose `request.url` is the route's template, and the response is the same bare 500 body the existing Phase 175 and 207 tests assert; a route raising a mapped domain error (404) and a 422 each send nothing, with the control that the same assertion goes red when a 404 is captured on purpose; with `sample` returning True every request sends one transaction whose duration is the middleware's, with it returning False none, and `/healthz` none either way; with no DSN, `app.state.telemetry.enabled` is False, `threading.active_count()` is unchanged by `create_app`, and every existing API test passes unchanged; `wholetree.sh` fast mode is green with the two seams in place.
