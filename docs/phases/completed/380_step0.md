## S0-3: the questions, for the operator

Both items change existing live rows (a key written on all 1060 rows; 104
junction rows removed), so each deploy will be a dry run whose diff is
shown before the live apply. These questions are about the design, before
any of that is built.

### Q1. F129: what the key is

- **1A: a readable slug in each seed entry, generated once and then
  frozen (recommended).** A new `key` field, e.g.
  `vespa-small-carburetted-scooters`, made once from the current make and
  title, made unique, and written into the 112 seed files. From then on a
  title, make or model edit does not touch it. A new column
  `known_issues.row_key`, unique, carries it; the identity index moves to
  it. Live: all 1060 rows get their key by the one-to-one match above.
- **1B: source file plus ordinal.** Derived, so nothing is written into
  the seed. But reordering or inserting an entry in a file re-keys every
  entry after it.
- **1C: a UUID written into each seed entry.** Stable, like 1A, but
  opaque: a reviewer cannot tell which row a migration names.

### Q2. F129: what the key lets a reload do

- **2A: insert-only, as now; a content change goes through a migration
  that targets the key (recommended).** A re-seed never overwrites a live
  row silently, and each content edit stays a reviewed live diff. It
  retires 255B's old/new literal pairs: `reconcile_255B_rows`,
  `backfill_row_applicability` and migration 065's pattern become `UPDATE
  … WHERE row_key = ?`.
- **2B: the loader updates a live row from its seed entry by key.** A
  content edit becomes a seed edit plus a reload. But any reload rewrites
  live rows, and the per-edit approval lives in a reload rather than a
  migration diff.

### Q3. F142: the 35 models with no evidence of their own make

The 90 with evidence are assigned in either option, and each model under
another make leaves the junction (104 rows).
- **3A: keep the 35 under every make their row names, as today, listed
  and counted (recommended).** No row loses a reader. A test fails if an
  assigned model appears under another make, and the 35 are a pinned list
  that can only shrink as evidence arrives.
- **3B: withhold the 35** from every make until assigned. Fail-closed:
  their rows reach no owner of those models.
- **3C: assign all 125 by hand in the seed now,** as content decisions,
  each one a stop, before 380 builds.

The prose fragments read as models (S0-2) are F135's question (what the
corpus means by a "model") and stay parked with section F.
