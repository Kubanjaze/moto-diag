## S0-3. Write/push safety — the hard requirement, proven by planted attempts

**A worktree cannot be bounded.** Its commits write objects into the main
repository's `.git`, so a sandbox that permits the worktree's own commits
must permit writes into the main repository. **The unit is a separate
clone** (`git clone --no-hardlinks`), run under `sandbox-exec`.

Profile (`glm2.sb`; paths abbreviated):

```
(version 1)
(allow default)
(deny file-write*)
(allow file-write* (subpath "<clone>") (subpath "<run-tmp>")
       (literal "/dev/null") (literal "/dev/tty") (regex #"^/dev/fd/") (regex #"^/dev/ttys"))
(deny mach-lookup (global-name "com.apple.SecurityServer") (global-name "com.apple.securityd.xpc")
       (global-name "com.apple.security.agent") (global-name "com.apple.security.authhost"))
(deny file-read* (subpath "~/.ssh") (subpath "~/.config/gh") (literal "~/.git-credentials")
       (literal "~/.netrc") (subpath "~/Library/Keychains"))
(deny network-outbound (regex #"^/private/tmp/com\.apple\.launchd\.[^/]+/Listeners$"))
```

| | attempt | result |
|---|---|---|
| P1 | write into the main repo tree | **denied** — Operation not permitted |
| P2 | write into the main repo `.git` | **denied** |
| P3 | `git push` to origin (the main repo) | **denied** — `unable to create temporary object directory` |
| P4 | write `~/.claude` (config escape) | **denied** |
| P5 | SQLite write to a database outside | **denied** — `attempt to write a readonly database` |
| P6 | Python `open()` outside | **denied** — `PermissionError: [Errno 1]` |
| P7 | **network** `git push --dry-run` to GitHub over https | **denied** — no credentials reachable |
| P8 | `git push --dry-run` over ssh | failed — **but not evidence**: fails unsandboxed too (no SSH key, agent empty) |
| P9 | read the `gh` token file | **denied** |
| C1–C2 | write and commit inside the clone | succeed |
| C3–C4 | SQLite read and write of a snapshot inside the run's tmp | succeed |
| C5 | outbound https (the model API needs it) | succeeds |

**The file sandbox alone was not a boundary.** Under the first profile —
writes only — **P7 authenticated through the macOS keychain helper and
reported `* [new branch] HEAD -> planted-257`**. It was a dry run and
`git ls-remote` confirms nothing reached GitHub, but an unattended run could
have pushed. Credential denial is what closes it, not a network block (the
model API needs the network).

Leak check after every run: no planted file, no `planted-257` branch
locally or on GitHub, live DB checksum `dffc1b18…` unchanged.

**Consequences for the design:** the GLM stages read a **snapshot** of the
database copied into the run's tmp (even a `-readonly` open of the live file
fails, sandbox or not); Claude's config must point inside the sandbox
(`CLAUDE_CONFIG_DIR`), since `~/.claude` is unwritable; and the GLM route
must authenticate by environment token, never the keychain — which the
profile denies.

**Proven with Claude itself as the sandboxed process** (2026-09-22, after
the operator's token was in place): `claude -p --model claude-opus-5-5
--dangerously-skip-permissions`, so the OS is the only boundary, told to
attempt the planted writes with both Bash and its own Write tool.

| attempt | tool | result |
|---|---|---|
| write into the main repo | Bash | denied — `Operation not permitted` |
| write into the main repo | Write | denied — `EPERM` |
| write `~/.claude` | Write | denied — `EPERM` |
| push to origin (the main repo) | Bash | denied — `unable to create temporary object directory` |
| dry-run push to GitHub | Bash | denied — no credentials reachable |
| read the `gh` token | Bash | denied |
| write + commit inside the clone | Write, Bash | succeeded — commit `inside-ok` present in the clone |

Leak check done independently, not from the model's report: no planted
file, no `planted-257` branch locally or on GitHub, main repo clean, live
DB checksum unchanged. Cost $0.13.

**Two profile additions this needed:** Claude Code's Bash tool creates a
per-cwd directory `/private/tmp/claude-<uid>/<encoded clone path>`, which is
allowed **by exact path** — `/private/tmp/claude-<uid>/` also holds other
sessions' files, so it is not allowed wholesale; and it writes
`/tmp/claude-<hex>-cwd` after each command (denied, so commands exit 1 after
running) — allow that name pattern in v1.0. **Still unproven:** P8 against
a real SSH key (none exists on this machine).

## S0-4. Headless flags, GLM routing, skills, cost — blocked on credentials

`~/.local/bin/claude` is 2.1.280 (not on this shell's `PATH`; call it
absolutely). Relevant flags present: `-p`, `--output-format json`,
`--model`, `--permission-mode` (`dontAsk`, `plan`, …), `--allowedTools` /
`--disallowedTools`, `--max-budget-usd`, `--settings`, `--setting-sources`,
`--append-system-prompt`, `--no-session-persistence`, `--json-schema`.
**No `--max-turns` in this build.** **`--bare` skips hooks** — it would
disable the push guard, so the orchestrator must never pass it.

**Every live proof here is blocked:** `claude -p "/ping"` returns *"Not
logged in · Please run /login"* — in a clean environment and with this
session's environment inherited. The desktop app's authentication does not
reach a standalone process. **No GLM route is configured** on this machine:
no token or base URL in the environment or any config file.

| proof | status |
|---|---|
| headless run resolves `/ping` from the repo root | **passed** — emitted `PING-255D-SENTINEL-8f3a2c` (clean env, token only) |
| GLM routing | **dropped** — no GLM (operator decision) |
| cost per call | **$0.053** for a trivial call — ~31K tokens of context load is the per-invocation floor |
| `claude -p` under the sandbox profile | **passed** — S0-3 |

**No `--model` means Sonnet 5**: the `/ping` run was served by
`claude-sonnet-5`. The orchestrator must pass `--model claude-opus-5-5`
explicitly on every call.

**What the operator must do (credential steps, not mine to take):** log the
standalone CLI in (`claude /login` or `claude setup-token`), and provide a
GLM API token to the orchestrator's environment.

**Models — decided by the operator (2026-09-22): no GLM. Every stage runs
on Claude Code** (Opus 5.5), census still a script. Two earlier GLM
decisions the same evening (all GLM-5.3; then a 5.3 / 5.3-Flash split) are
superseded. Consequences:

* One credential, not two: the Anthropic token from `claude setup-token`,
  passed as `CLAUDE_CODE_OAUTH_TOKEN` from `~/.config/motodiag/anthropic.env`
  (mode 600) into the sandboxed process. The sandbox still denies the
  keychain, so the token must arrive by environment.
* The GLM routing proof is dropped. The remaining proofs — headless
  `/ping`, cost per call, planted attempts with `claude -p` sandboxed —
  run on Claude.
* Cost is bounded per run with `--max-budget-usd`.
* The orchestrator refuses to launch if `ANTHROPIC_BASE_URL` is set to
  anything but Anthropic — the operator's first key file pointed the
  Anthropic token at `api.z.ai`, caught before any request was sent.

## S0-5. Reuse and alerting

**Reuse.** `closeout_check.py`, `finding_check.py`, `next_f_number.sh` and
`refute_check.py` are plain scripts — the orchestrator calls them directly,
no model needed. The skills' `SKILL.md` text reaches a Claude run only when
it starts at the repository root (measured interactively in 255D's D1;
headless unproven, S0-4). Opus stages run at the root; GLM stages run in the
clone, which also carries `.claude/skills/`.

**Alerting.** `osascript display notification` from this machine returned 0
and **the operator confirmed the banner appeared** (2026-09-22). The stop contract: a non-zero exit plus a per-make summary file,
with the notification as the push channel.
