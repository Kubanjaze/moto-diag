### What the internet would reach: the code side

PR 98's audit (its plan page, `docs/reports/2026-11-25_409_prebuild_plan.md`,
"What the internet would reach") was re-read against today's tree. The
anonymous surface is unchanged since `21bf8f4`: 210 added a CLI, not a
route. Read again here:

- **The caller's address behind the tunnel.** uvicorn 0.54's
  `ProxyHeadersMiddleware` trusts `X-Forwarded-For` only from
  `127.0.0.1` (its default) and takes the right-most untrusted address
  (`reversed(x_forwarded_for_hosts)`), the one Cloudflare's edge appends.
  A caller's own `X-Forwarded-For` cannot pick their bucket. The desktop's
  uvicorn version is read by the measurement block before the tunnel goes
  on (older uvicorn took the left-most address).
- **500s carry no exception text** (`api/errors.py`, the 500 handler:
  `detail=None`).
- **No JSON route takes a body near 1 MiB:** no route under `src/motodiag/api/`
  takes base64; files go as multipart, which the cap leaves to each route.
- **The login guard's trade-off, written down:** the name-wide total (50
  failures in 15 minutes from every address together) holds that name for
  its real owner too, so a stranger who knows a username can keep it
  locked out from the internet while they keep guessing. That is the
  price of stopping a guess spread over many addresses. With no shops yet,
  the only names are the operator's own; the window is 15 minutes, a
  restart clears it, and the tailnet name is held the same way. Kept as PR
  98 built it; v1.0 records it under Rule-1 stops as no stop (the limits
  are new, not a change to an existing threshold).
