# Phase 259 — Step 0: what the tree and the library hold before the plan

**Measured 2026-09-24, before v1.0.** Scripts in the builder session tmp
(`scratch/`); every load-bearing figure below is re-derived by the
phase's tests (`tests/test_phase259_ppi_engine.py`).

## S0-1 — the plan's nouns in `src/` (and tests): greenfield-shaped extension

Vocabulary: `pre-purchase`, `PPI`, `compression`, `leak-down`/`leakdown`,
`oil sample`, `fuel quality`, `starter`, `charging health`, `visual
inspection` — over `src/` and `tests/`, case-insensitive, whole words
where a word exists.

- **`PPI` as a workflow category exists; no PPI content does.** Phase
  114's substrate carries `WorkflowCategory.PPI`, tables
  `workflow_templates` + `checklist_items` (migration 007), and a
  seeded stub: `generic_ppi_v1` with **5** starter items, 2 of them
  engine-relevant (a compression test, a fluid inspection) and 3
  chassis-side. The substrate is 370 lines: `models.py` (104),
  `template_repo.py` (234), `__init__.py` (32).
- **No leak-down, oil-sample or fuel-quality content anywhere.**
  Zero hits in `src/` and `tests/` for those subjects.
- **The substrate has no consumer.** `grep -rn "template_repo\|workflows"`
  over `src/motodiag/cli/` and `src/motodiag/api/`: **0 imports**. No
  command, no route, no scheduled job calls a single function of the
  package Phase 114 built. Its own docstring says Track N will populate
  it; nothing can reach it today.
- **Adjacent, not competing:** `engine/workflows.py` is Phase 82's
  in-memory *diagnostic* engine (a different thing); `engine/wiring.py`
  carries generic charging-circuit reference floors (unrelated substrate,
  not a PPI checklist).

**Decision: extension, not greenfield, not reshape.** The tables, models
and CRUD exist; the phase adds content (a migration) and the one thing
the substrate never got — a front door (a CLI command group). No schema
change beyond the content migration. No reshape: `WorkflowCategory.PPI`
already enumerates this workflow type.

## S0-2 — what a content migration may rely on, measured

- `checklist_items` has **no unique constraint** (only
  `idx_checklist_template`); migration 007's `INSERT OR IGNORE` there is
  inert as a guard. Consequence: 259's seed must live inside the
  one-shot migration journal (as 007's own seed does), never in a
  re-runnable seed path — a re-run would duplicate items silently.
- `workflow_templates.slug` **is** unique, so template-level
  `INSERT OR IGNORE` is a real guard.
- `generic_ppi_v1`'s description promises "Track N phase 259 expands
  with engine-specific content" — a forward pointer this phase either
  fulfills in that template or re-points (D1/D5 in the v1.0).
- Phase 114's own tests pin `generic_ppi_v1` at **5 items** and
  `len(list_templates()) >= 2` — relative or untouched pins, so a third
  template and a description UPDATE break nothing. Verified after the
  build: 114's file green.

## S0-4 — the powertrain boundary

The six subjects are ICE subjects: an electric machine has no
compression, oil, fuel or starter. The substrate's default is all three
powertrains; using it would offer this protocol to a Zero. The
mechanism that exists is `applicable_powertrains` + `list_templates`'s
documented JSON-substring filter (114's own risk note) — the phase sets
`["ice","hybrid"]` and pins the electric exclusion with a test.
