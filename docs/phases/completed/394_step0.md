## S0-4. How a stage that cannot start behaves today

- A rank's `Stop` is caught by `Fleet.run_stage`, said once on the issue
  (`say_stopped`, marker `stopped rank=<rank> run=<run>`), label unchanged.
  `due_for` counts that marker, so the stage is not due again until the
  label is applied again: **a `Stop` already stops once.**
- An `OSError` is not a `Stop`: `run_stage` ends the journal as
  `failed: OSError: …` and re-raises; `main` logs "cycle failed"; the
  label is still due, so the next cycle begins a new run directory, whose
  `started` marker is new (`tag()` adds `run=<run>`), and posts again.
  That is the 69.
- `xo.review` and `yeoman.digest` catch `Stop` themselves (XO's own stop
  comment; the digest's `STOP`), so a launch failure raised as `Stop`
  stops them once too.

## S0-5. Decisions (rule 1: none is a stop)

- **The brief goes on stdin for every rank, fenced and not**:
  `rank_call.command` loses its prompt argument and `rank_call.call` passes
  `input=prompt`; `FencedRunner` hands `input` to the fence instead of
  `/dev/null`. The Engineer's brief is written to the run directory and
  opened as the session's stdin (its stdout already goes to a file).
- **A launch failure is a `Stop`**: `rank_call.LaunchFailed(Stop)`, raised
  where the process is started (`rank_call.call`, `FencedRunner.session`),
  so every existing stop path applies unchanged.
- **"started" once per stage run**: a stage run again after its previous
  run *failed* (journal outcome `failed: …`) with that run's `started`
  marker still the issue's last rank comment does not say "started" again;
  the journal records whose marker stands. A stop, a verdict or any other
  rank comment in between makes it a new stage run, which says it.
- **`call_key` stays compatible**: it drops `-p` and the following
  argument only when that argument is not a flag, so a journal written
  before this phase keys the same call the same way.
