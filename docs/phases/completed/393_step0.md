## S0-7. The two bugs, measured

- **The PDF escape.** `reporting/renderers.py:471` defines `_escape` for
  reportlab's markup; line 517, `from html import escape as _escape`,
  rebinds it, so `PdfReportRenderer.render` runs `html.escape`. Measured
  with pypdf on `a38a36b`: a PDF built from `She said "hi" & it's <ok> >
  fine` reads back exactly that, in the title, a heading, the body and a
  bullet. reportlab renders `&quot;` and `&#x27;`, so **the shadowing has
  no effect a reader of today's PDFs can see**: the defect is the wrong
  function, and the reportlab one dead. The fix stands; its test proves
  the text and the function.
- **The erase.** `memory/erase.py:84`, `:105` and `:146` catch every
  `Exception` and pass. A locked database at the first `DELETE` already
  raises (it is outside any handler); an error inside the guidance table's
  handler is swallowed. The test plants the error SQLite gives for a
  locked table at each handled statement.

## S0-9. What runs where

- **GitHub Actions.** The repository is public; the workflow needs no
  secret. `tests/conftest.py` reads `live.json` through `live.where()`
  and tolerates its absence (`live.LiveElsewhere`); whether the ratchet
  tests run there is proven by the workflow's first run, recorded in the
  log.
- **The fence.** `fence.sh` sets `HOME=/fleet/run/home`, so
  `regression.sh`'s coverage JSON lands in the check run's own directory,
  which the dispatcher reads after the run.
