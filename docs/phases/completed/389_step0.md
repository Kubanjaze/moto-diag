## S0-1. The GLM builder report, and the 258–260 pattern

From `docs/reports/2026-09-25_glm_builder_findings.md` (every figure
there measured; its last section names the artefacts each came from).
Each figure below was read with `grep -n` on that file:

- **Fresh-session review cost** (`grep -n "advisor session\|fresh session" docs/reports/2026-09-25_glm_builder_findings.md`).
  Opus's landing of 259 ran in the long
  advisor session: 109 calls, 55.5M tokens read. 260's ran in a fresh
  session: 130 calls, 23.1M read. Each advisor call re-read about 500K
  tokens of conversation, which made 259's landing "about 2.4× more
  expensive in reads" (§5). The report's verdict (§8) names a fresh,
  small-context review as one of four conditions for a cheap builder to
  pay.
- **Integration defects** (`grep -n "Full-suite runs\|Introduced by" docs/reports/2026-09-25_glm_builder_findings.md`).
  Every GLM phase needed fixes before merge
  (§4's table, ten defects): a schema-head literal (F124), a test reading
  live, a stale allowlist pinned in three files, a migration that stripped
  its predecessor's rollback. "The defects are integration defects. They
  break conventions that live in tests GLM did not run." The full
  regression caught four of them, one run at a time: 258 and 260 each
  needed 2 full runs, 259 needed 3 (§2).
- **Trap 1 (§1):** "The shared virtualenv is an *editable* install of the
  main repo. A clone using it tests master's code unless `PYTHONPATH`
  points at the clone." Measured here again in S0-5.

**How this phase prevents the pattern.**
1. **The Engineer runs the full suite itself before the PR**, inside its
   fence, with `regression.sh` (rule 3), and its brief names every trap
   the report and this Step 0 found.
2. **The dispatcher runs it again, with no model**: a fresh fenced clone
   of the Engineer's final commit, `wholetree.sh --full` then
   `regression.sh`, and the PR opens only when that run passes and its
   counts equal the Engineer's line. The report's own lesson is that a
   builder's numbers were not trusted until someone else re-ran them; here
   the re-run is a script reading an exit code.
3. **Each review is a fresh `claude -p` call** (the Red Team, the Captain's
   recommendation, the XO), never a long session: the 2.4× above.
4. **The fleet's venv is built at the fence's paths** (S0-5), so a stage
   tests its own clone's code, never master's.

## S0-4. The fence: the branch in, the identity out

**The branch goes in as the clone.** The dispatcher clones the phase
branch from its own mirror before the fence starts (388's `clone()`), and
the clone is the only writable tree a rank sees. Nothing inside the fence
can push: there is no network but the model API (388's gate), and no
credential.

**The push identity never enters the fence.** On this desktop a `git
push` authenticates through `gh auth git-credential`
(`git config --show-origin --get-regexp 'credential.*'`: the helper in
`~/.gitconfig`), which is the operator's login (`gh auth status`: account
`Kubanjaze`, scopes `repo`, `workflow`, `gist`, `read:org`). So the
dispatcher pushes from outside the fence, after the stage, and names the
identity explicitly on that one command (a credential helper set with
`-c`, the token in that process's environment), never the ambient one:
- the fleet's machine user's token, from a mode-600 file beside the
  model's (`~/.config/motodiag/fleet-github.env`), once the operator has
  made the account (pre-approval (a));
- until then, the operator's login, only for an issue planted as a trial
  (pre-approval (b)); any other issue gets a `needs-hands` comment and
  nothing is pushed.

`gh api repos/Kubanjaze/moto-diag --jq '{visibility, …}'` → public;
`gh api repos/Kubanjaze/moto-diag/rulesets --jq length` → 0;
`… /collaborators --jq '.[].login'` → `Kubanjaze` only.

**Before any push, the dispatcher's own gate**, because the push guard is
a hook that fires only inside a Claude session's tool loop: the branch is
`phase-<N>-*` and never `master`; the push is a fast-forward; each rank
touches only its paths (the Science Officer its step-0 report and prompt,
the Captain its plan, the Engineer anything but the guards, the fleet's
own code, `.claude/settings.json`, `CLAUDE.md` and other phases' rows); no
added line holds a credential; `roadmap_check.check_tree(clone)` passes;
and the commit was tested by a run no model touched. **Whole-tree records
written inside a fence cannot be trusted**: `wholetree.py` signs them with
`~/.config/motodiag/wholetree.key`, and inside the fence `$HOME` is the
run directory, so each fenced run makes its own key, one the rank inside
can read. The dispatcher therefore runs `wholetree.sh` itself, in a fresh
fenced clone with no model, and reads the exit code.

**The token, in a seat that has Bash** (388's open item). Measured with a
probe script run by a fenced Haiku session with Bash allowed, writing
counts and process names only to a file, never the token (the pattern
`sk-ant-oat01-[A-Za-z0-9_-]{20}`, so the probe's own command line cannot
match):

| how the token goes in | the Bash tool's own environment | `/proc/*/environ` holding it | command lines, readable fds | the call |
|---|---|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` in the environment (388's fence) | 0 | 3: bwrap, the network helper, claude | none | served Haiku |
| the same, with `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` | no reading | no reading | no reading | Bash did not start: the scrub turns on Claude Code's own Bash sandbox, which needs `socat` (not installed) |
| a pipe on fd 3, `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3` | 0 | none | none | served Haiku |

In all of them a read of the parent's memory was refused
(`/proc/sys/kernel/yama/ptrace_scope` = 1), and
`grep -rlaE 'sk-ant-oat01-…' <run dirs>` found the token in no file
afterwards. Both variables are in this Claude Code (2.1.310:
`strings $(readlink -f $(which claude)) | grep -oE 'CLAUDE_CODE_[A-Z_]*(SCRUB|FILE_DESCRIPTOR)[A-Z_]*'`).
**So every stage gets the token on a pipe**: the fence passes fd 3 through
to claude and sets the variable; the token is never in an environment a
rank's command can read.

**The repository's guards fire inside the fence.** Its hooks use
`${CLAUDE_PROJECT_DIR}` (`.claude/settings.json`). A fenced Haiku session
told to run `sed -i 's/zzqq/zzqq/' src/motodiag/__init__.py` got "edit
guard: blocked — `sed -i` edits a file in place, and is blocked wherever it
points", and the file's mtime did not change.
